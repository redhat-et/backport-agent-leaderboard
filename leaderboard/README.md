# Backport Bench — Leaderboard App

A standalone Gradio web app for visualizing benchmark results. The app reads aggregated JSON result files and displays an interactive leaderboard with search, filtering, and sorting.

## Installation

Install in development mode:

```bash
pip install -e ".[dev]"
```

This installs all dependencies including Gradio and Pandas.

## Running Locally

From the leaderboard directory:

```bash
python app.py
```

The app will be available at http://localhost:7860

By default, it reads results from `../results/aggregated/`. You can customize this by setting the `RESULTS_DIR` environment variable:

```bash
RESULTS_DIR=/path/to/results/aggregated python app.py
```

## Features

### Tabs

#### 1. Leaderboard Tab

Aggregated view showing one row per tool configuration. Columns:

- **Category** — Icon indicating open-source vs. proprietary
- **Name** — Tool display name (linked to tool URL if available)
- **Avg Score** — Average pass rate across all benchmarks
- **Per-benchmark columns** — Pass rate for each benchmark subset (pivoted)

Default sort: Avg Score descending

Interactive features:
- Search by tool name
- Filter by category (open-source / proprietary)
- Sort by any column (click header)

#### 2. Benchmark Runs Tab

Detailed view showing one row per individual benchmark run. Columns:

- **Category** — Open-source vs. proprietary indicator
- **Name** — Tool display name
- **Benchmark** — Benchmark subset identifier
- **Score** — Pass rate as a percentage
- **Avg Cost Per Task (USD)** — Mean cost per backport entry
- **Avg Seconds Per Task** — Mean wall-clock time per entry
- **Avg Input Tokens Per Task** — Mean input tokens per entry (optional, via column picker)
- **Avg Output Tokens Per Task** — Mean output tokens per entry (optional, via column picker)

Default columns shown: Category, Name, Benchmark, Score, Avg Cost Per Task

Interactive features:
- Search by tool name
- Filter by category
- Column picker to show/hide additional metrics
- Sort by any column

#### 3. About Tab

Explains the benchmark methodology, how to read the tables, and how to submit results. Content is loaded from `about.md`.

### Auto-Refresh

The app automatically reloads result data every 5 minutes to pick up new benchmark runs without requiring a restart.

## Data Format

The app reads aggregated JSON files from `results/aggregated/`. Each file represents one benchmark run:

```json
{
  "benchmark": {
    "name": "backportbench-java",
    "repo": "owner/repo",
    "num_tasks": 250,
    "url": "https://..."
  },
  "tool": {
    "display_name": "My Tool / Opus 4.6",
    "is_oss": true,
    "url": "https://..."
  },
  "metrics": {
    "score": 0.72,
    "n_tasks": 250,
    "n_errors": 3,
    "cost_usd": 185.50,
    "mean_cost_usd_per_task": 0.74,
    "mean_time_seconds_per_task": 180,
    "mean_input_tokens_per_task": 200000,
    "mean_output_tokens_per_task": 4800
  }
}
```

These aggregated files are generated by the orchestrator's `backport-bench leaderboard` command or written directly if you have custom aggregation logic.

## Deployment

### HuggingFace Spaces

The app is deployable to HuggingFace Spaces:

1. Create a new Space on HuggingFace
2. Select "Gradio" as the SDK
3. Push your code:

```bash
git clone https://huggingface.co/spaces/YOUR_USERNAME/YOUR_SPACE
cd YOUR_SPACE
cp -r /path/to/leaderboard/* .
cp -r /path/to/results/aggregated ./results/
git add .
git commit -m "Initial leaderboard deployment"
git push
```

4. HuggingFace will automatically install dependencies from `pyproject.toml` and run `app.py`

### Docker

Build and run with Docker:

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY pyproject.toml .
RUN pip install -e .

COPY . .

EXPOSE 7860

CMD ["python", "app.py"]
```

```bash
docker build -t backport-leaderboard .
docker run -p 7860:7860 -v /path/to/results:/app/results backport-leaderboard
```

### Environment Variables

- `RESULTS_DIR` — Path to aggregated results directory (default: `../results/aggregated/`)
- `REFRESH_INTERVAL` — Auto-refresh interval in seconds (default: 300)

## Architecture

The app consists of three modules:

- **app.py** — Gradio app entry point, layout definition, event handlers
- **data_loader.py** — Reads JSON files, builds DataFrames for each tab
- **about.md** — Markdown content for the About tab

### Data Loading (`data_loader.py`)

**`load_results(results_dir)`**
- Scans `results_dir` for `*.json` files
- Parses each file and returns a list of result dictionaries

**`build_leaderboard_df(results)`**
- Groups results by tool display name
- Computes average score across benchmarks
- Pivots per-benchmark scores into columns
- Returns a pandas DataFrame

**`build_runs_df(results)`**
- Creates one row per result
- Extracts metrics (score, cost, time, tokens)
- Returns a pandas DataFrame

Both functions handle missing fields gracefully and provide default values.
